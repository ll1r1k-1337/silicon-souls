# Эксплуатация

## 1. Логи

Логи должны быть структурированными.

Минимальные поля:

- timestamp;
- level;
- service;
- traceId;
- projectId, если применимо;
- sessionId, если применимо;
- llmCallId, если применимо;
- message;
- errorCode.

## 2. Что логировать

API:

- входящие запросы;
- ошибки валидации;
- сообщения, которые инициируют LLM update;
- результат schema validation для LLM output;
- факт применения или отклонения обновления документации;
- ошибки доступа к базе;
- LLM provider;
- model;
- duration;
- retry count для synchronous repair;
- failure reason.

Не логировать:

- plaintext API keys;
- полный prompt, если он содержит пользовательскую конфиденциальную информацию;
- секреты из настроек provider.

## 3. Метрики

Минимальные метрики:

- количество созданных проектов;
- количество сообщений чата;
- количество успешных обновлений документации;
- количество LLM calls;
- среднее время LLM ответа;
- процент failed LLM calls;
- процент validation_failed LLM outputs;
- token usage, если доступно.

## 4. Алерты

Нужны алерты на:

- API недоступен;
- PostgreSQL недоступен;
- LLM provider возвращает много ошибок;
- доля validation_failed ответов превышает норму;
- среднее время LLM ответа превышает порог;
- закончилась квота или бюджет LLM;
- rate limit часто срабатывает для обычного пользовательского сценария.

## 5. Backup и restore

Что нужно сохранять:

- проекты;
- сообщения;
- текущую документацию;
- версии документации;
- LLM call metadata;
- audit events;
- настройки LLM без plaintext секретов.

Правила:

- backup PostgreSQL выполняется регулярно;
- restore процедура должна быть проверена до production;
- backup не должен содержать plaintext API keys.

## 6. Обработка инцидентов

Для каждого серьёзного инцидента фиксируется:

- время начала;
- симптомы;
- затронутые пользователи или проекты;
- причина;
- временное решение;
- постоянное исправление;
- preventive action.

## 7. Поддержка пользователя

Пользователь должен видеть понятные ошибки:

- LLM provider недоступен;
- API key неверный;
- квота LLM исчерпана;
- изменение документации не удалось, но текущий документ не повреждён;
- запрос слишком большой;
- ответ LLM не прошёл валидацию.
